# Quickshell Modules

## When to Use
Use when building, fixing, or debugging any quickshell module, panel, or popup in ~/dotfiles/.config/quickshell — especially when the bar disappears, IPC targets go missing, a new window misbehaves, or redesigning UI (ControlCenter, DriveHealth, panels). ALL new or restyled UI goes through the Design-first workflow below: HTML/CSS options in the browser, user picks, then port to QML. Ported UI follows the Bento design language (step 8) with colors ONLY from the system theme, and the layout rules in steps 22-28. Bug fixes and logic-only changes skip the design phase.

### Scope note — global web forbiddens vs Bento (read this first)
The `frontend-design` global forbidden rules (black-white-first, no gradients/glass/chips/uppercase-labels) apply to web/app/marketing UI — they do NOT override the Bento house style inside ~/dotfiles rice. For quickshell modules, 0.3–0.5 alpha glass fills, 22–26px chips, uppercase labels with 1.2–1.3 letter-spacing, and gradient/slider fills are required, not banned. Apply the global bans only when building non-rice UI.

Exploration is the exception: during the Design-first workflow, use the frontend-design skill and the design skills freely. Options may break Bento tokens (radii, label style, chip shapes) because the point is to see different directions. The Bento tokens apply again at port time, unless the user picks a design that deviates (see Design-first step 6).

### Color rule (applies to every phase)
SYSTEM THEME ALWAYS. Every color comes from the Matugen-driven `colors` object in QML, and from the copied `colors.css` variables in HTML options. No hex literals, no `Qt.rgba` literals, no hardcoded fallback colors, anywhere. Whatever hue the wallpaper produces is correct: the palette is amber today and may be teal tomorrow. Design by ROLE (primary, secondary, tertiary, surface, surfaceVariant, outline, foreground, background, error), never by hue.

## Design-first workflow (new UI and redesigns)
1. **Load the design skills.** Read the frontend-design skill and any design skill in the skills list before writing options. Use them freely in this phase.
2. **Find and copy the live theme.** Locate the Matugen output that Colors.qml reads (`rg -l 'colors.css' ~/dotfiles | head`; confirm by reading Colors.qml, never guess the path or variable names). Copy it into `/tmp/ui-options/<module>/colors.css` so file:// previews work. At the top of each option, add a small `:root` alias block mapping the CSS variables to the QML role names, so the HTML reads like the QML will. Options use `var(--role)` only, no hex.
3. **Use the real font.** Options use `font-family: "FiraCode Nerd Font"` so glyph previews match the shell. Icons: Nerd Font glyphs or Phosphor SVG. Glyphs still get verified by NAME at port time (step 11).
4. **Make three options, not three skins.** Each is a distinct direction (different layout, density, and shape language), saved as `/tmp/ui-options/<module>/option-a.html`, `option-b.html`, `option-c.html`. Each option is ONE self-contained file: CSS and JS inline, the colors.css variables pasted into its `<style>`, no sibling files (the user wants one file to open and copy). Each shows real content shaped like the module's actual properties, and every state: rest, hover, selected, loading, empty, error, and, for anything with a link or connection, the lost/reconnecting state. Show the keybinds on screen. Include motion using the motion tokens in step 21. Add `index.html` that shows the three side by side with A/B/C labels, so one command opens everything.
5. **Open in the browser and stop.** Run `xdg-open /tmp/ui-options/<module>/index.html`, then wait for the user to pick. Do not touch any .qml file before a pick. The user may mix ("A's header, C's rows") or ask for another round: iterate in HTML until they say port it. When the user says an option is ugly or too busy, remove decoration first (status dots, glow, gradients, extra borders, icon chips) before adding anything; simpler is the default direction. Opening the options with xdg-open is allowed and expected. It does not count as the unasked screenshot banned in Verification step 10.
6. **Check the pick against the house tokens.** If the picked design deviates from Bento tokens (radii, label style, chip size, track height), ask once whether the deviation becomes the new house style or stays local to this module. If house, update step 8 and the Bento check in this skill in the same change. Never silently fork the design language.
7. **Port to QML.** Translate the chosen HTML, keeping existing logic byte-identical (step 20). Follow module kind, ownership, IPC, and glass steps (2–7, 10, 14), and the layout rules (22–28). Colors come only from `colors.*` (Color rule above). Animations use step 21. Then run the normal Verification loop.

## Procedure
1. Read ~/dotfiles/.config/quickshell/AGENTS.md first — canonical path is always quickshell -p ~/.config/quickshell, identical string everywhere.
2. Pick the module kind: PILL = Item bar widget (property var colors, signal openRequested(), readonly derived props, no window — e.g. Battery.qml). PANEL = PanelWindow dropdown (anchors all four sides, ExclusionMode.Ignore, transparent, visible: root.open so closed means fully gone, Esc + click-outside backdrop in the SAME window — sibling PanelWindows stack unpredictably. Gives it a qs-* WlrLayershell.namespace matched by blur layerrules). CARD = FloatingWindow centered popup (title, implicitWidth/Height plus minimumSize/maximumSize, visible: root.open, Hypr float+center+size windowrules for both class quickshell and org.quickshell, and NEVER any WlrLayershell.* prop).
3. Ownership: quick bar toggles live in Bar.qml as Named { id: x; colors: palette } so pills wire by id (onOpenRequested: wifiPanel.open = !wifiPanel.open). Standalone popups live in shell.qml top level as Name { colors: barPalette }. Every visual module takes property var colors (only LockScreen/NetRate are exempt).
4. IpcHandler is always target: "<name>" with function toggle(): void { root.open = !root.open } (calendar pinning via bar is the lone exception). Add the Hypr bind as quickshell -p ~/.config/quickshell ipc call <target> toggle. Esc must close the surface.
5. Develop new modules in a scratch instance (/tmp/pltest + QtObject color stub) so the live bar never breaks; bisect poison with an outsider-canary IpcHandler — if outsider is missing from ipc show, halve the module until it registers.
6. Parse-check edits before restarting: timeout 6 quickshell -p ~/.config/quickshell 2>&1 | grep -E 'ERROR|Loaded' (a timeout is fine, it just runs the config for 6s). Only when it prints Configuration Loaded, do the real restart.
7. Restart fresh (pkill -x quickshell; setsid quickshell -p ~/.config/quickshell) for verdicts — never trust hot reload alone. Hypr rule changes need hyprctl reload.
8. STYLE ported UI in the BENTO design language (house style, keep consistent): CARD = 16px radius, colors.alpha(colors.surface,0.4) fill, 1px border colors.alpha(colors.outline,0.14). LABEL = Bold uppercase, letterSpacing 1.2-1.3, colors.alpha(colors.outline,0.55) (section) / 0.65 (widget title); size by surface: 7px for small widgets (up to ~360px wide), 9px for full-size card windows (~600px+ wide), see step 23. CHIP = 22-26px circle, alpha(accent,0.15) fill + alpha(accent,0.3) border, 12px glyph in accent. SLIDER/PROGRESS = 7px track colors.alpha(colors.surfaceVariant,0.55), gradient or 0.9-alpha accent fill, 18px handle with colors.background fill + 2px accent border (thin 4px bars are fine for inline data meters). NUMBER = 14px ExtraBold for headline values, 10px ExtraBold for stats/%. GLYPH = FiraCode Nerd Font everywhere, icons as glyphs not images; when a needed glyph isn't in the font or fails verification (step 11), fall back to a Phosphor Icons SVG at the same size/color instead of forcing a wrong or missing Nerd Font codepoint — never leave a tofu box or an invented codepoint in place. COLOR = system theme only (see Color rule): `colors.*` roles, never hex. ACCENTS by purpose: primary = brand+interactive, secondary = complementary, tertiary = data/network. Values on graphs must be readable (PEAK label + per-bar values) — never bare bars.
9. NO X CLOSE ICONS. Every panel/card closes via Esc + click-outside backdrop (already required in steps 2 and 4) — do not add a visible X/close-glyph button in the corner of a card or panel. It clutters the bento layout and duplicates a dismissal path that already exists; if a surface genuinely needs an explicit close affordance beyond Esc/click-outside, ask before adding one rather than defaulting to an X icon.
10. GLASSMORPHIC IS THE HOUSE LOOK, apply it consistently across every surface type, not just FloatingWindow popups: PANEL dropdowns and inline CARD widgets get the same treatment as the floating-window glass recipe (step 14) — transparent window background, semi-transparent surface fill in the 0.3-0.5 alpha range (never 0.9+, that kills the blur-behind effect), a subtle 1px outline border, and the compositor's blur-behind layerrule applied via the qs-* namespace. Don't let one popup type end up flat/opaque while another is glass — the whole shell should read as one consistent glass language.
11. ICONS must verify by GLYPH NAME, never by charset presence. Nerd/MDI codepoints drift between font builds: U+F01C1 was file-pdf-box upstream but is md-currency_usd (a literal $) in this FiraCode build — charset presence checks passed and it still rendered wrong. Verify every codepoint (old and new) with fontTools before shipping:
  python3 -c "from fontTools.ttLib import TTFont; print(TTFont('/usr/share/fonts/TTF/FiraCodeNerdFont-Regular.ttf').getBestCmap()[0xF1C1])"
  The printed name must match intent (fa-file_pdf_o, md-folder, fa-check…). Presence-only checks (fc-query charset, getBestCmap key test) are NOT sufficient. If no correct Nerd Font glyph exists for the concept, use a Phosphor Icons SVG instead of guessing a codepoint.
12. FLOATING WINDOW sizing is content-driven, not rule-driven. Hypr `size` rules apply at map, then QML content implicit size resizes the window inside min/max — every converted window opened at min/max clamps instead of its rule. So: set min/max honestly around the MEASURED open size (hyprctl clients -j), pin scroll views with Layout.preferredHeight, make grid cells fluid (cellWidth: Math.max(150, Math.floor(view.width / Math.max(2, Math.floor(view.width / 178)))), delegates width: GridView.view.cellWidth - 8), and never trust the rule alone. Position quirk: expect odd top-left offsets on quickshell windows even with `center on` — cosmetic, not worth chasing.
13. NO `var` statement blocks inside property bindings — the parser throws `Unexpected token ';'` and the whole shell fails to load (no bar, no IPC). `text: { var f = …; return … }` is fatal; use ternary expressions or named functions/properties instead. `function(e){…}` handlers and onX blocks are fine.
14. FLOATING WINDOW glass recipe (all three required): `color: "transparent"` on the window itself (default paints opaque behind your glass), inner rect colors.alpha(colors.surface, 0.4) (0.9+ kills the blur-behind effect), 16px radius. Converted overlays must also drop the click-blocker backdrop MouseArea and the Wayland import when unused.
15. RENAME SWEEP: when a window title changes, grep windowrules.conf + bindings.conf + KeybindsPanel.qml + looknfeel.conf layerrules together — a stale title (PhoneLink vs PhoneBridge) fails silently, rules just never match. Delete the dead qs-* layerrules and `hyprctl reload`.
16. UNBIND ORDER in bindings.conf: `unbind` kills previously-defined matches, so a stale unbind placed AFTER a new bind silently deletes it (SUPER CTRL SPACE case). Put unbinds directly ABOVE the bind they clear, then confirm with `hyprctl binds | grep -B8 <arg>` that exactly one entry exists.
17. MATUGEN full-regen danger: `matugen image <wall>` without the exact original flags can flip the entire palette (sage→teal incident) AND dirty every generated file. Prefer rendering a single template from live colors.css; after ANY matugen run immediately `git diff --stat` and revert collateral (colors.css, cava, rofi, zed) before doing anything else.
18. PARTIAL COMMITS: the tree is always dirty with other work — stage only your hunks via a hunk-split patch (`git diff -U3 <file> | awk … > /tmp/hunk.patch` with diff header prepended, `git apply --cached`) so nothing pre-existing rides along. Generated-file moves (stowing ~/.config/zathura into dotfiles + relative symlink mirroring the quickshell one) are committable; untracked helper bins are not.
19. Reuse existing helpers before writing new ones (fmtDurShort, fmt, condGlyph, NetRate rx/tx history).
20. Preserve embedded logic byte-identical when redesigning: Process blocks, properties, functions, IpcHandler, timers stay untouched; only the visual layer is edited (user requirement for ControlCenter/DriveHealth). When the file is on disk, EDIT IN PLACE: split at the `// ===== UI =====` marker (or the nearest section comment) and replace only the visual section with a script or str_replace, so the logic half is never retyped. Retyping a ~1000-line file to change its UI risks silent logic drift. Only when the file exists solely as pasted text in the conversation, reproduce it whole, and say so.
21. MOTION. Animate only changes the user caused, things entering or leaving, and live numbers or progress. Four durations: press 90ms, hover 140ms, enter 220ms (window pop 280ms), layout 320ms. Two curves: OUT (fast start, soft landing) and POP (small overshoot, only for things that appear). In QML use `easing.type: Easing.BezierSpline` with a 6-number `easing.bezierCurve`, ending in `1, 1`: OUT = [0.2, 0.8, 0.2, 1, 1, 1], POP = [0.34, 1.35, 0.64, 1, 1, 1]. Use `Behavior` for state changes (scale, color, width) and `add`/`remove`/`displaced` `Transition`s on ListView and GridView for lists, not per-delegate animations. No looping decoration, no more than three things moving at once. Honor reduced motion where the shell exposes a setting. Keep the same durations and curves in the HTML options (cubic-bezier(.2,.8,.2,1) and cubic-bezier(.34,1.35,.64,1)) so the pick matches what ships.

## Layout rules (ported UI) — proportions are arithmetic, do them before writing QML
22. HEIGHT BUDGET FIRST. Before writing any layout, write the budget as a comment above the root ColumnLayout: window height, minus top and bottom margins, minus (blocks - 1) x spacing, gives the content height. List every block's fixed or preferred height. Exactly ONE block fills (`Layout.fillHeight: true`, with a `Layout.minimumHeight`); everything else is fixed. The sum of the fixed blocks plus spacing must leave the filling block at least its minimum, with the optional blocks (queue, banners) counted at their maximum. If the sum overshoots, cut or shrink blocks; never rely on the layout squeezing the scroll area. The PhoneBridge original needed ~724px in a 700px window, which is why nothing sat right.
23. ONE TYPE SCALE and ONE SPACING SCALE per module, declared in a comment at the top of the UI section. Full-size card windows (~600px+): 9px caps labels, 11px body, 13px titles and headline values; never below 9px. Small widgets and pills keep the 7px label token. Spacing: one outer margin, one gap between blocks, one inner padding for cards (e.g. 16 / 10 / 14). A third size or a one-off padding needs a reason. Mixed 7/8/9/10/11/12px text and ad-hoc padding is what "proportions are off" usually means.
24. LAYOUT STRUCTURE. Every block is full width and left aligned; one block per row except deliberate pairs (data + hotspot). Rows of actions use equal columns: `Layout.fillWidth: true` plus `Layout.preferredWidth: 1` on each child, not a Flow of mixed-width tiles. Drop zones are wide and short (~56px), not tall boxes. Reusable pieces (caption, surface, button) are declared once as inline `component`s and reused; do not restyle the same thing three ways.
25. HOVER MOTION IN LAYOUTS. A Layout owns its children's x, y and width; a binding on `y` or `x` for a hover lift is silently overridden. Lift buttons and tiles with `transform: Translate { y: hovered ? -2 : 0; Behavior on y {...} }`. Every button must visibly move on hover. Row slide-in uses `Translate { x }` the same way.
26. STATUS NEVER ADDS A LAYOUT ITEM. Transient messages replace the key-hint footer in place (same fixed height), instead of inserting a pill that pushes the browser around. Banners that can appear and disappear must be in the height budget or overlay the content.
27. CONNECTION STATES ARE FIRST-CLASS. Anything that rides a link (adb over wifi, hotspot) needs: connected, switching, lost-and-watching (with the retry countdown), and re-linked, each readable in the header and in the empty state of the main area. Track "was connected, now gone" as its own property so the UI can say "Link lost" instead of the same text as "never paired".
28. NO DECORATION WITHOUT A JOB. Drop status dots, glow, gradients on bars, dashed borders, thumbnails, and icon chips unless the user asked for them or a state is unreadable without them. Prefer text labels over glyphs when a glyph can't be verified (step 11) or when the source shows blank private-use characters; draw tiny shapes (signal bars) with Rectangles instead.

## Verifying layout without a browser or screenshots
Vision is not needed and not trusted for layout. Dump the live item tree as text and check it with rules.
- **Dump:** add a dev-only `function dump(): string` to the module's IpcHandler that walks `card` children and prints one line per visible item: type, `mapToItem(card,0,0)` x,y, width x height, and for text items the string, `font.pixelSize` and `truncated`. Example:

```qml
function dumpUi() {
    var out = []
    function walk(it, d) {
        if (!it.visible) return
        var p = it.mapToItem(card, 0, 0)
        var line = "  ".repeat(d) + String(it).split("(")[0] + " @" +
            Math.round(p.x) + "," + Math.round(p.y) + " " +
            Math.round(it.width) + "x" + Math.round(it.height)
        if (it.text !== undefined)
            line += ' "' + it.text + '" ' + it.font.pixelSize + "px" + (it.truncated ? " TRUNCATED" : "")
        out.push(line)
        for (var i = 0; i < it.children.length; i++) walk(it.children[i], d + 1)
    }
    walk(card, 0)
    return out.join("\n")
}
```
  Call it with `quickshell -p ~/.config/quickshell ipc call <target> dump`. This snippet is untested in the shell; parse-check it like any edit. Remove the handler before committing unless the user wants it kept. A text dump is not a screenshot: it is allowed and expected (Verification step 10).
- **Rule checks on the dump:** child outside its parent or the window; sibling text overlap; `TRUNCATED` text; fonts under 9px in full-size windows; click targets under ~24px; left or right edges that miss each other by 1-3px; uneven gaps between full-width siblings; a block's content taller than its height; the fill block below its minimum height.
- **ASCII wireframe:** draw each item as a box on a character grid (about 1 column per 5px, 1 row per 10px) to read proportions and alignment at a glance.
- **Snapshot diff:** save the dump after a state the user approved and diff it after each later change; report exactly which items moved or resized.
- **Loop:** change, parse-check, fresh restart, dump, run the checks, read the wireframe, fix, repeat. The user still verifies the final look.

## Pitfalls
- Charset presence is NOT glyph verification (see step 11) — always confirm the glyph NAME matches intent; MDI drift turned file-pdf-box into a dollar sign.
- ListModel delegates have NO `modelData` (named roles only) — passing it yields undefined (the Wallshelf double-click bug). Plain-JS-array models DO have modelData; prefer `wAt(index)` style accessors.
- Search-while-loading races: `if(loading){ queued=true; return }` swallows a reset — carry a second `resetQueued` flag and drain both at every completion path.
- Never call a function from a handler without grepping its definition first — `clearFinished` shipped called-but-undefined and threw on click.
- Never ship an invented Nerd Font codepoint — a wrong codepoint renders as a tofu box. Verify candidates against the actual font file first: fc-query --format=%{charset} <font.ttf> (parse bare hex tokens and 'a-b' ranges), or copy glyphs verbatim from existing modules (NowPlaying: prev 󰒮, play 󰐊, pause 󰏤, next 󰒭 — note prev/next are the OPPOSITE of the Material Design glyph names). Reuse proven glyphs: 󰂛/󰂚 dnd, 󰃠 sun, 󰇚/󰕒 dl/ul, 󰐥 power, 󰌾 lock, 󰉏 camera, 󰅌 clipboard, 󰳨 vibrate, 󰕽/󰕾/󰝟 volume. If none of these fit and verification (step 11) fails, use a Phosphor Icons SVG rather than a guessed codepoint.
- Adding a visible X close button on a panel/card — the surface already closes via Esc/click-outside; an X icon is redundant clutter and breaks the bento look.
- A glassmorphic FloatingWindow next to a flat/opaque PanelWindow reads as inconsistent — apply the same glass treatment (transparent window bg, 0.3-0.5 alpha surface fill, blur-behind layerrule) to every surface type.
- Hardcoded hex or `Qt.rgba` literals in QML (or hex in HTML options) break the system-theme rule: the module stays amber after the wallpaper changes. Always `colors.*` or `var(--role)`.
- Porting before the user picks an option. Options go to the browser first, QML changes only after a pick.
- Making three options that are the same layout in different skins. They must differ in structure, density, and shape language, or the pick means nothing.
- Guessing the colors.css path or its variable names. Read Colors.qml and the actual file first.
- `Easing.Bezier` with a 4-number array. Qt's enum is `Easing.BezierSpline` and the curve takes 6 numbers ending in `1, 1`. The PackageManager file used the 4-number form, so check it and any copy of it. Confirm the animation actually curves after a fresh restart, and check the log for easing warnings.
- Ids are not properties: `root.searchTimer.restart()` throws because `searchTimer` is an id, not a property of `root`. Call `searchTimer.restart()` directly. Grep new handlers for `root.<someId>` before shipping.
- Fallback palettes (`QtObject` stand-ins for `colors`) must carry every property the UI reads, including non-color ones like `fontSans`; a missing one is `undefined` at startup and logs errors. Add the property; do not add new hex colors to it.
- A hover lift written as `y:` or `x:` on a layout child does nothing (layout owns it); use `transform: Translate` (step 25).
- Pasted QML can arrive with private-use glyph characters stripped to empty strings. Do not "restore" them from guesses; use text or drawn shapes (step 28) and tell the user which icons were replaced.
- A status pill or banner added as a layout item makes the whole column jump when it appears (step 26).
- Overflowing the window: an unbudgeted column silently squeezes the scroll area. Do the arithmetic in step 22 before writing the layout.

## Verification
1. hyprctl layers shows qs-bar (1584x54) plus your window's namespace when open
2. quickshell ipc --pid <main-pid> show lists every target including the new one
3. Fresh instance log has 0 TypeError lines
4. ipc call <target> toggle opens the window (check floating + size via hyprctl clients -j) and toggles it shut
5. Parse check: timeout 6 quickshell -p ~/.config/quickshell 2>&1 prints 'Configuration Loaded' with no ERROR lines before the restart verdict
6. UI check: open the panel, run the dump (see "Verifying layout without a browser"), and confirm no overlaps (every mixed-height row label vertically centered), no `TRUNCATED` text or ellipsis on elided texts, no layout jumps when long names or status messages swap in, and the filling block at or above its minimum height
7. Bento check: new/styled widgets use only the token values (radii 12/16, label 7px/1.3 for small widgets or 9px/1.2 for full-size windows, chip 22-26, track 7px or 4px inline meter), unless the user approved a deviation in Design-first step 6 — no visible X close icons, glass treatment consistent across every surface type. Color check: `rg -n '#[0-9a-fA-F]{3,8}\b|Qt\.rgba' <changed .qml files>` returns nothing, so every color comes from `colors.*` and follows the system theme.
8. Icon check: every glyph verified by name (step 11); any glyph that failed verification or doesn't exist in the font is a Phosphor Icons SVG or plain text instead, not a guessed codepoint
9. Commit only your files; leave pre-existing dirty files (PLUGINS.md, .local/bin, plan.md) alone unless asked
10. Delivery loop that works: parse-check → fresh restart (never trust hot reload) → 0 TypeError → `quickshell -p ~/.config/quickshell ipc --pid <pid> call <target> toggle` → confirm geometry via `hyprctl clients -j` (at/size/floating) → run the text dump and its checks → user verifies visually. Do NOT screenshot for the user unasked — they verify. (The HTML options opened with xdg-open in Design-first step 5 are a separate, requested step, and the text dump is not a screenshot.)
11. Design-first check (new UI only): three options existed, the user picked before any .qml changed, and the final QML matches the picked option's structure, states, and motion.
12. Report honestly what was verified. If the module was never run (no restart, no dump), say it was only checked by reading and arithmetic; never describe a layout as visually confirmed unless the user confirmed it.
